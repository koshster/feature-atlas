# Feature Atlas

Mechanistic interpretability project: train sparse autoencoders on GPT-2 small activations, discover interpretable features, and use them to explain and steer the model. Flagship resume project for an undergrad, so correctness and explainability matter more than speed.

The full design is in `docs/PLAN.md`. Phase status, results and failure stories are in `docs/PROGRESS.md`. Read both before starting work.

## Current status

Phase 1 (foundations): activation pipeline built and tested. See `docs/PROGRESS.md` for what remains.

## Hard rules

- **Everything must be free.** If a choice would cost money or need a credit card, stop and propose a free alternative. No paid APIs; LLM calls use Ollama or Hugging Face local models.
- **Phase gates.** Do not start a phase until the previous one is complete and the user has confirmed.
- **Each phase ends with:** working, tested, committed code; a `docs/PROGRESS.md` entry; and a summary of key concepts and likely interview questions.
- **Design choices:** briefly present options and a recommendation rather than deciding silently.

## Architecture rules

- Data flow: model → activations → SAE → analysis → demo.
- Dependencies point one way. `src/feature_atlas/models/backend.py` is the **only** module that imports `transformer_lens`.
- The SAE takes plain tensors and must stay testable with synthetic data.
- The SAE, training loop and metrics are written from scratch. Core code must never import `sae_lens`; it belongs only in the optional `[baseline]` extra.
- Training activations come through `ActivationSource`: online for real runs, disk shards for tests, evaluation and analysis.
- Notebooks stay thin: install a pinned commit, set up the environment, call package functions. No core logic lives only in a notebook.

## Known pitfalls

- Keep `transformer-lens>=3.9,<4`. TL 4 removed `HookedTransformer`, and SAELens requires TL below 4.
- The reference `gpt2-small-res-jb` SAEs expect `center_writing_weights: true`. Compare SAEs only on activations produced with identical settings.
- λ (L1 coefficient) isn't comparable between implementations. Compare at matched L0 and explained variance.
- Free GPU sessions die without warning. Checkpoints must be atomic and synced to the Hub, and quota counts idle session time.
- `stop_at_layer=N` stops before block N, so that block's `hook_resid_pre` never fires. Use the returned residual, as `ModelBackend.activations` does.
- Position 0 of every context has about 30× the norm of other positions, whatever the token, and holds 88% of the squared magnitude. It can dominate L2 loss and explained variance.
- Report online-source reproducibility as statistical. Only shard-based resume is bit-exact.

## Engineering standards

- Python 3.11+, installable package under `src/`, managed with uv.
- Pydantic plus YAML config. Every result must be reproducible from a config file and a fixed seed.
- Type hints throughout; ruff for lint and format; mypy; pre-commit running both.
- pytest on CPU, in under a few minutes, using tiny models and synthetic data. Tests needing network carry a `slow` marker.
- Docstrings on public functions. Comment tensor shapes where they aren't obvious, and explain non-obvious math and design decisions, since the user must explain them in interviews.
- Deterministic seeding, structured logging, clear error messages, no hardcoded paths.
- Never commit weights, activation caches or datasets. Those go on Hugging Face Hub or are regenerated by scripts.

```bash
uv run pytest -m slow                      # network tests
uv run ruff check . && uv run ruff format . # lint and format
uv run mypy src                            # type check
uv run pre-commit run --all-files          # all hooks
uv run atlas --help                        # CLI
uv run atlas cache --config configs/smoke.yaml      # small real cache
uv run atlas benchmark --config configs/smoke.yaml  # tokens per second
```
